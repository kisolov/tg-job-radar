# radar — отказы и гонки

| Ситуация | Что происходит | Защита |
|---|---|---|
| Две записи одного аккаунта одновременно (флуд + учёт вступления) | второй `save` получает `StaleAccount` | conditional update `WHERE version=:v`; `AccountService` перечитывает и повторяет до 3 раз; алерт — только после успешной записи |
| Повторное `banned`/`unauthorized` по тому же аккаунту | алерт не дублируется | алерт только при смене статуса |
| Импорт с неавторизованной сессией | аккаунт сохранён `unauthorized`, в пул не попадает | `SessionProbe.check` до сохранения |
| Две корутины закрепляют одну группу | одна выигрывает, вторая получает `False` и берёт следующий источник | conditional write `assigned_account_id IS NULL`; Postgres блокирует строку до коммита первой |
| Аккаунт упёрся в лимит членства во время закрепления | закрепление откатывается целиком, счётчик не растёт | `membership_count < cap` в той же транзакции; `AssignWork` исключает аккаунт из кандидатов |
| Курсор опроса пытаются сдвинуть назад (опоздавший опрос) | курсор не меняется | `WHERE last_message_id < :m` |
| Одно сообщение пришло live и опросом / из двух аккаунтов | обрабатывается один раз | unique `messages(source_id, message_id)`, `ON CONFLICT DO NOTHING`; проигравший ничего не делает (R2) |
| Рестарт процесса | опрос продолжается с курсора из БД; зависшие `resolving` → `candidate` (`reset_resolving` при старте) | курсор и статусы в БД |
| Копии одной вакансии приходят одновременно из разных чатов | один кластер, все копии привязаны к нему | `pg_advisory_xact_lock(hashtext('findings-dedup'))` на «найти/создать кластер»; фейк — `asyncio.Lock` |
| Две доставки одной находки (повторный запуск `DeliverAccepted`, ретрай) | карточка уходит один раз | conditional claim `accepted → delivering` |
| Процесс упал между claim и отправкой | находка ждёт до `CLAIM_STALE_S` (10 мин), затем `RedeliverStale` возвращает её в `accepted` и она уходит один раз | `stale_claims(claimed_at < now − CLAIM_STALE_S)` |
| Процесс упал между отправкой и `mark_delivered` | после `CLAIM_STALE_S` карточка уйдёт повторно — **единственный известный путь к дублю** | цена принята: окно — миллисекунды между ответом Telegram и UPDATE |
| Копия пришла, пока карточка отправлялась | событие не порождается (статус `delivering`) | после `mark_delivered` число копий сверяется и карточка правится |
| Рестарт теряет очередь `CopyAttached` | «Также в» обновится со следующей копией | R9 eventual |
| Параллельные пакеты проверяют дневной лимит LLM | не больше лимита в сумме резервов | атомарный conditional `reserve` (R8) |
| NeuroAPI вернул мусор / меньше элементов / 5xx / таймаут | один повтор; затем `LlmUnavailable`, сообщения остаются `pending`; пропущенные id — тоже `pending` | парсер отбрасывает невалидные элементы; резерв снимается (`release`) |
| Дневной лимит LLM исчерпан | отбор на паузе до конца суток UTC, алерт владельцу раз в сутки | `ScreeningService.reserve` |
| Источник снят (`/remove`, отсев, вытеснение), а аккаунт ещё в группе | слот членства занят до выхода | воркер аккаунта выходит (`leave`) и только затем `release`; если нас уже выгнали — сразу `release` |
| Автопополнение тащит мусорные чаты | `discovery`-кандидаты с низшим приоритетом; не по теме / не по-русски / ретранслятор → `rejected` | `SourceService.vet` после резолва |
| Чтение лимита/интервала → вступление → запись счётчика (R5) | действия аккаунта не пересекаются | одна корутина `AccountWorker` на аккаунт (вступление, резолв, опрос последовательно) + запись `Account` по `version`; **допущение одной реплики** — при разнесении на процессы перейти на `FOR UPDATE SKIP LOCKED` по аккаунту |
| Статус сменился на `banned`, пока идёт чтение | ничего не ломается: Telegram сам отказывает забаненному; воркер видит не-`active` на следующем шаге и останавливается | статус пишется по `version`; воркер завершает себя по ошибке Telegram или статусу |
| Потерян `USERBOT_STORE_KEY` | сессии не расшифровать | аккаунты ввести заново (`radar accounts login`) |

### Ошибки Telegram (маппинг в `telethon_gateway.map_error`)

| Ошибка Telethon | Порт | Реакция |
|---|---|---|
| `FloodWaitError`, `FloodPremiumWaitError` | `TgFlood(s)` | вступление/резолв: `apply_flood` (пауза s, ×1.5 интервал, −5 лимит); > 1 ч на вступлении → `flood_wait` + алерт, на резолве/опросе → только пауза резолва + алерт, чтение идёт (I1); опрос: пауза опроса аккаунта на s |
| `UserDeactivatedBanError`, `PhoneNumberBannedError` | `TgBanned` | `banned`, алерт, все источники аккаунта освобождаются, корутина аккаунта завершается; остальные работают |
| `UserDeactivatedError`, `AuthKey*`, `SessionRevoked/Expired` | `TgUnauthorized` | `unauthorized`, то же |
| `ChannelInvalidError` | `TgPeerStale` | хэш чужого аккаунта: `requeue` — закрепление снято, хэш стёрт, повторный резолв (не `dead`) |
| `ChannelPrivate`, `UsernameInvalid/NotOccupied`, `UserBannedInChannel`, `InviteHashExpired/Invalid`, `ChannelBanned`, `ChatForbidden` | `TgSourceGone` | источник `dead`, закрепление снимается, счётчик членств −1 |
| `InviteRequestSentError` | `TgJoinRequested` | источник `rejected`, но закрепление и слот остаются: одобренная заявка не собьёт R4 (M3) |
| `ChannelsTooMuchError` | `TgChannelsTooMuch` | `external_memberships = cap − membership_count` (чаты вне учёта), пауза вступлений 1 ч (M4) |
| прочие на одном источнике (`ChatIdInvalid`, таймаут, …) | — | опрос: лог, `set_polled`, следующий источник (I3); выход из чата: лог, слот освобождается |
| `ConnectionError` / клиент отключён (`is_connected()` = False) | — | корутина аккаунта завершается, `PoolRunner.sync` (раз в 60 с) создаёт её со свежим клиентом (I2) |
| Инвайт привёл в уже известный чат | — | источник `rejected`, выход из чата, слот освобождается (R7) |

### Панель

| Ситуация | Что видно | Что делать |
|---|---|---|
| Нет cookie / истекла / сменился `USERBOT_STORE_KEY` без `WEB_SECRET` | «Нужен вход», `/api/*` → 401 (с доступными способами входа) | `/web` в боте или пароль |
| Неверный пароль | 403 через 1 с | — |
| Рестарт процесса | журнал алертов панели пуст (в памяти) | при боте алерты остались в Telegram |
| Ссылка входа старше 10 мин или уже открыта | 403 «Ссылка входа недействительна» | новая `/web` |
| Перезапуск процесса между `/web` и открытием ссылки | ссылка ещё действует (nonce-память пуста) — повторное открытие той же ссылки после рестарта тоже пройдёт | приемлемо: окно 10 мин, ссылка приходит только владельцу |
| Запрос без `X-Radar: 1` (чужой сайт) | 403 | — |
| Падение задачи `web` | панель недоступна, остальное работает | `supervise` перезапустит |

### LLM (I4)

| Ситуация | Что происходит |
|---|---|
| NeuroAPI вернул мусор | оплаченные токены (`LlmUnavailable.spent`) идут в `daily_stats` и лимит R8; пакет остаётся pending, `llm_attempts +1`, находки уходят в конец очереди |
| NeuroAPI недоступен (сеть, HTTP) | простой: токены, если были, учтены; попытки не тратятся, пакет повторится через 60 с |
| Модель пропустила id в ответе | этой находке `llm_attempts +1` |
| `llm_attempts` достиг 3 | находка → `failed` (в панели — «Ошибка LLM», вкладка «Отклонены»), очередь не стоит |
| LLM недоступен дольше часа подряд | алерт владельцу, не чаще раза в сутки |

### Обработка сообщения (I5)

| Ситуация | Что происходит |
|---|---|
| `submit` упал (таймаут пула, ошибка БД) | отметка в `messages` стирается, курсор источника не сдвигается; следующий опрос берёт сообщение снова. Live-сообщение группы подхватит опрос вступленной группы |
| Процесс упал между `remember` и `done` | на старте `purge_unprocessed` стирает такие записи; опрос перечитает |
| Остаточный риск | если позже успешно обработано сообщение с бо́льшим id того же чата (курсор только вперёд), упавшее раньше уже не перечитается |
| Пул соединений | `pool_size=20, max_overflow=20, pool_timeout=60` — всплеск live-апдейтов не выбирает пул |

### Доставка карточки (I6)

| Ситуация | Что происходит |
|---|---|
| Поле LLM (деньги, формат, суть, причина) длинное | обрезается до 300 символов, названия чатов до 80 — карточка ≤ 4096 |
| Telegram отклонил HTML-карточку (`TelegramBadRequest` → `DeliveryRejected`) | одна попытка простым текстом (`to_plain`: ссылки выписаны, `tg://` убран) |
| Отклонена и она | находка → `failed` (в панели «Не обработана»), алерт владельцу; повторов нет |
| Сеть / 5xx | `unclaim`, повтор при следующей доставке (как раньше) |

### Импорт tdata

| Ситуация | Что видно |
|---|---|
| Включён локальный код-пароль, `--passcode` не дан или неверный | «tdata защищена локальным код-паролем: укажите верный --passcode», ничего не импортировано |
| Папка не tdata / битые файлы | «Не похоже на tdata Telegram Desktop (…)» |
| Сессия разлогинена — номер не узнать | ошибка с подсказкой `--phone`; с `--phone` аккаунт сохраняется как `unauthorized` |
| `--phone` при нескольких аккаунтах в tdata | ошибка: номер подходит только для одного |
| `opentele` 1.15.1 не принимает объект `Session` в `ToTelethon` | обход в адаптере: `session=None`, ключ переносится в `StringSession` |
